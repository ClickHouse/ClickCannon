## 数据生成流程概述

ClickCannon 的数据生成采用**多线程流水线架构**：

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│   Profile    │────▶│   Worker     │────▶│  Insert to   │
│  (定义规则)   │     │  (生成数据)   │     │  ClickHouse  │
└──────────────┘     └──────────────┘     └──────────────┘
      ▲                    │                     ▲
      │                    ▼                     │
   Filler              BlockQueue ──────────────┘
   (填充逻辑)
```

### 关键流程步骤

1. **配置加载** (`config.yaml`)
   - 指定 `data_type`: logs/traces/profiles
   - 选择 `profile`: otel_demo (默认)
   - 设置 threads, rows_per_block 等参数

2. **Profile 初始化**
   - 从 `profileRegistry` 加载指定的 Profile
   - Profile 定义每个字段的生成器 (Gen)
   - 生成器包括: Pool, RandStr, Hex, UUID, Map 等

3. **Worker 生成数据**
   - 每个 Worker 线程独立运行
   - 从 BlockPool 获取空白 Block
   - 调用 Filler.Fill() 填充数据
   - 将填充好的 Block 推送到 InsertQueue

4. **数据写入 ClickHouse**
   - Insert Worker 从 InsertQueue 消费 Block
   - 使用 ch-go 库流式批量写入
   - 支持压缩、负载均衡、连接重用等优化

## 核心架构组件

### 1. Columns 定义 (`columns_logs.go`, `columns_traces.go`)

**作用**: 定义表结构，对应 ClickHouse 的表字段

```go
type GenLogsColumns struct {
    Timestamp          proto.ColDateTime64Raw
    TraceID            proto.ColStr
    SpanID             proto.ColStr
    ServiceName        *proto.ColLowCardinality[string]
    Body               proto.ColStr
    ResourceAttributes *proto.ColMap[string, string]
    // ... 更多字段
}
```

**关键点**:
- 每个字段对应 ClickHouse 的一个列
- 字段类型必须匹配 proto 定义
- LowCardinality 用于优化高重复度字符串

### 2. Profile 定义 (`profile.go`, `profile_otel_demo.go`)

**作用**: 定义每个字段的数据生成规则

```go
func newProfileOtelDemo() *Profile {
    return NewProfile("otel_demo").
        WithServiceName(Pool("api-gateway", "auth-service", "user-service")).
        WithSeverityText(Pool("INFO", "ERROR", "WARN", "DEBUG")).
        WithBody(Pool("HTTP request completed", "Database query executed")).
        WithResourceAttrs(Map(
            K(1.0, "cloud.provider", "aws"),
            K(0.99, "cloud.region", "us-east-1", "us-west-2"),
            K(0.95, "k8s.namespace.name", Pool("ingress", "payments")),
        ))
}
```

**生成器类型**:
- `Const(v)` - 固定值
- `Pool(...)` - 从列表中随机选择
- `RandStr(n)` - 随机字符串
- `Hex(n)` - 十六进制字符串
- `UUID()` - UUID 生成
- `IP()` - IP 地址
- `Int(min, max)` - 整数范围
- `Map(K(...))` - Map 类型字段

### 3. Filler 逻辑 (`filler_logs.go`)

**作用**: 将 Profile 规则转换为实际数据，填充到 Columns

```go
func (f *LogsFiller) Fill(ctx context.Context, rng *Rng, cols *GenLogsColumns, n int) int {
    for i := 0; i < n; i++ {
        cols.Timestamp.Data = append(...)
        cols.TraceID.Append(rng.TraceID())
        cols.ServiceName.Append(f.p.ServiceName.Generate(rng))
        cols.Body.Append(f.p.Body.Generate(rng))
        cols.ResourceAttributes.Append(f.p.ResourceAttrs.Generate(rng))
        // ...
    }
}
```

### 4. Generator (`generator.go`)

**作用**: 提供基础的数据生成原语

```go
type Gen interface {
    Generate(rng *Rng) string
}
```

## 配置化方案设计

### 设计目标

1. ✅ **零代码修改** - 仅通过配置文件添加字段
2. ✅ **灵活的数据类型** - 支持 String, Int, Float, Bool, Map
3. ✅ **丰富的生成规则** - Pool, Random, UUID, Timestamp, Expression 等
4. ✅ **向后兼容** - 不影响现有 Profile 和代码生成方式

### 架构设计

```
config.yaml
  ├── generate.profile_config_file: "profiles/custom_logs.yaml"
  └── generate.enable_custom_fields: true

profiles/custom_logs.yaml
  ├── base_profile: "otel_demo"  # 继承现有 Profile
  ├── custom_fields:
  │   ├── user_id:
  │   │   ├── type: string
  │   │   └── generator: {type: uuid}
  │   ├── request_count:
  │   │   ├── type: int64
  │   │   └── generator: {type: int_range, min: 1, max: 10000}
  │   └── tags:
  │       ├── type: map
  │       └── generator: {type: map, keys: [...], values: [...]}
```


### 实现步骤


#### 1. 创建配置文件结构定义

创建 `internal/generate/custom_config.go`:

```go
package generate

type CustomFieldsConfig struct {
    Version       string                   `yaml:"version"`
    DataType      string                   `yaml:"data_type"`
    BaseProfile   string                   `yaml:"base_profile"`
    CustomFields  map[string]FieldConfig   `yaml:"custom_fields"`
    OverrideFields map[string]FieldOverride `yaml:"override_fields"`
}

type FieldConfig struct {
    Type           string          `yaml:"type"`  // string, int64, float64, bool, map
    ClickHouseType string          `yaml:"clickhouse_type"`
    Generator      GeneratorConfig `yaml:"generator"`
}

type GeneratorConfig struct {
    Type   string                 `yaml:"type"`
    // 通用参数
    Values []interface{}          `yaml:"values"`
    Min    interface{}            `yaml:"min"`
    Max    interface{}            `yaml:"max"`
    // Pool 参数
    Weights []float64             `yaml:"weights"`
    // String 参数
    Length  int                   `yaml:"length"`
    Charset string                `yaml:"charset"`
    Prefix  string                `yaml:"prefix"`
    // Map 参数
    Keys    []MapKeyConfig        `yaml:"keys"`
    // 条件参数
    Condition *ConditionConfig    `yaml:"condition"`
    IfTrue    *GeneratorConfig    `yaml:"if_true"`
    IfFalse   *GeneratorConfig    `yaml:"if_false"`
}

type MapKeyConfig struct {
    Key              string          `yaml:"key"`
    Probability      float64         `yaml:"probability"`
    ValueGenerator   GeneratorConfig `yaml:"value_generator"`
}
```


#### 2. 实现动态列管理

创建 `internal/generate/dynamic_columns.go`:

```go
package generate

import (
    "github.com/ClickHouse/ch-go/proto"
    "time"
)

type DynamicColumns struct {
    baseColumns block.SharedColumns  // 基础列 (从现有 Profile)
    customCols  map[string]proto.Column
    customNames []string
    allInput    proto.Input
}

func NewDynamicColumns(baseColumns block.SharedColumns, config *CustomFieldsConfig) *DynamicColumns {
    dc := &DynamicColumns{
        baseColumns: baseColumns,
        customCols:  make(map[string]proto.Column),
        customNames: make([]string, 0, len(config.CustomFields)),
    }
    
    // 为每个自定义字段创建对应的列
    for name, fieldCfg := range config.CustomFields {
        col := createColumnForType(fieldCfg.Type, fieldCfg.ClickHouseType)
        dc.customCols[name] = col
        dc.customNames = append(dc.customNames, name)
    }
    
    // 合并基础列和自定义列的 Input
    dc.rebuildInput()
    return dc
}

func createColumnForType(typeName, chType string) proto.Column {
    switch typeName {
    case "string":
        if chType == "LowCardinality(String)" {
            return newGenLowCardinality()
        }
        return &proto.ColStr{}
    case "int64":
        return &proto.ColInt64{}
    case "int32":
        return &proto.ColInt32{}
    case "float64":
        return &proto.ColFloat64{}
    case "map":
        return newGenMap()
    default:
        return &proto.ColStr{}  // 默认为字符串
    }
}
```

#### 3. 实现配置化生成器工厂

创建 `internal/generate/generator_factory.go`:

```go
package generate

import (
    "fmt"
    "strconv"
)

func BuildGeneratorFromConfig(cfg GeneratorConfig) (Gen, error) {
    switch cfg.Type {
    case "const":
        return Const(fmt.Sprint(cfg.Values[0])), nil
    
    case "pool":
        strVals := make([]string, len(cfg.Values))
        for i, v := range cfg.Values {
            strVals[i] = fmt.Sprint(v)
        }
        return Pool(strVals...), nil
    
    case "uuid":
        return UUID(), nil
    
    case "random_string":
        gen := RandStr(cfg.Length)
        if cfg.Prefix != "" {
            gen = gen.Prefix(cfg.Prefix)
        }
        return gen, nil
    
    case "hex":
        gen := Hex(cfg.Length)
        if cfg.Prefix != "" {
            gen = gen.Prefix(cfg.Prefix)
        }
        return gen, nil
    
    case "int_range":
        min := int(cfg.Min.(float64))
        max := int(cfg.Max.(float64))
        return Int(min, max), nil
    
    case "ip_v4":
        return IP(), nil
    
    case "timestamp":
        return Func(func(rng *Rng) string {
            // 实现时间戳生成逻辑
            return strconv.FormatInt(time.Now().UnixMilli(), 10)
        }), nil
    
    default:
        return nil, fmt.Errorf("unknown generator type: %s", cfg.Type)
    }
}
```

## 支持的生成器类型总结

| 生成器类型 | 用途 | 配置示例 |
|----------|------|---------|
| `const` | 固定值 | `type: const, value: "fixed"` |
| `pool` | 从列表随机选择 | `type: pool, values: ["a", "b"]` |
| `weighted_pool` | 带权重的选择 | `type: weighted_pool, values: [{value: "a", weight: 80}]` |
| `uuid` | UUID 生成 | `type: uuid` |
| `random_string` | 随机字符串 | `type: random_string, length: 16, charset: hex, prefix: "req_"` |
| `hex` | 十六进制字符串 | `type: hex, length: 32, prefix: "0x"` |
| `int_range` | 整数范围 | `type: int_range, min: 1, max: 1000` |
| `float_range` | 浮点数范围 | `type: float_range, min: 0.0, max: 100.0, precision: 2` |
| `ip_v4` | IPv4 地址 | `type: ip_v4, format: dotted` |
| `timestamp` | 时间戳 | `type: timestamp, format: unix_milli, offset_ms: -3600000` |
| `map` | Map 类型 | `type: map, keys: [{key: "k1", probability: 1.0, value_generator: {...}}]` |
| `conditional` | 条件生成 | `type: conditional, condition: {...}, if_true: {...}, if_false: {...}` |
| `template` | 模板字符串 | `type: template, template: "User {user_id} in {env}", fields: [...]` |

## 优势对比

### 代码方式 vs 配置化方式

| 特性 | 代码方式 | 配置化方式 |
|-----|---------|-----------|
| 添加字段 | 需修改 4 个文件 | 仅修改 YAML 配置 |
| 编译 | 需要重新编译 | 无需编译 |
| 学习成本 | 需要了解 Go 和代码结构 | 仅需了解 YAML 语法 |
| 灵活性 | 完全灵活 | 受配置语法限制 |
| 性能 | 最优 | 略有开销 (反射、动态列) |
| 可维护性 | 需要代码维护 | 配置即文档 |
| 快速迭代 | 慢 | 快 |
| 复杂逻辑 | 支持 | 受限 |

### 推荐使用场景

- **使用代码方式**:
  - 需要极致性能
  - 复杂的数据关联逻辑
  - 团队有 Go 开发能力

- **使用配置化方式**:
  - 快速添加简单字段
  - 频繁调整数据结构
  - 测试不同的数据分布
  - 非开发人员使用

## 快速开始示例

### 1. 创建自定义配置文件

```bash
mkdir -p profiles
cat > profiles/quickstart.yaml << 'EOF'
version: "1.0"
data_type: logs
base_profile: "otel_demo"

custom_fields:
  user_id:
    type: string
    generator:
      type: uuid
  
  request_count:
    type: int64
    generator:
      type: int_range
      min: 1
      max: 100
  
  environment:
    type: string
    clickhouse_type: LowCardinality(String)
    generator:
      type: pool
      values: ["dev", "prod"]
EOF
```

### 2. 更新配置

```yaml
# config.yaml
generate:
  enabled: true
  enable_custom_fields: true
  profile_config_file: "profiles/quickstart.yaml"
```

### 3. 创建 ClickHouse 表

```sql
CREATE TABLE my_logs
(
    -- 基础字段
    Timestamp DateTime64(9),
    ServiceName LowCardinality(String),
    Body String,
    -- ... 其他基础字段
    
    -- 自定义字段
    user_id String,
    request_count Int64,
    environment LowCardinality(String)
)
ENGINE = MergeTree()
ORDER BY (Timestamp);
```

### 4. 运行

```bash
./clickcannon -config config.yaml
```

## 常见问题


**Q: 自定义字段会影响性能吗?**

A: 会有轻微影响，主要来自:
- 动态列管理的反射开销
- 配置解析和生成器创建
- 建议对性能敏感的场景使用代码方式

**Q: 能同时使用代码 Profile 和自定义配置吗?**

A: 可以，`base_profile` 继承现有 Profile，自定义字段会额外添加。

**Q: 如何调试配置文件?**

A: 启用 debug 日志级别，会打印加载的字段和生成器信息。

**Q: 支持复杂的字段关联吗?**

A: Phase 2 会支持条件生成器和字段引用，可以实现基本的关联逻辑。

**Q: 配置文件放在哪里?**

A: 建议放在项目根目录下的 `profiles/` 目录，或使用绝对路径。

**Q: 可以动态修改配置吗?**

A: 当前需要重启程序，未来可以支持热重载。
